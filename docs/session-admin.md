# 会话管理页

入口 `/admin/session`，也可从 `/home` 或 `/admin/window` 进入。使用现有 `SHIM_KEY` 登录；不接收 URL 中的密钥，不需要增加部署变量。未设置主密钥时不挂载入口，未启用原生会话存储时不允许操作。

- **保留当前会话并重启连接**：停止空闲 CLI，校验已确认的存档，下一条真实消息续接。不会发送测试消息、调用模型或自动换成空白窗口。
- **放下当前会话**：选择模型和思考档位，勾选确认后提交。先备份旧会话，再为新会话保存配置。不要求先归档；未归档的旧对话不会自动注入新窗口。
- 后台正在回复、恢复、压缩、调用工具或有排队任务时拒绝操作。页面打开之后有新轮次开始，也需要刷新后重新确认，避免旧标签页操作了新的会话。
- 选定的模型与档位保存在私有卷，优先于 Kelivo 的模型请求，Telegram 同样使用这份设置。服务重新部署后仍生效；要改下一段配置，回到本页选择并确认。
- 完成操作后显示“等待下一条真实消息”是正常状态。已配对的 Telegram 或 Kelivo 都可以开始下一轮；自动心跳继续等待首轮成功保存。

## 记录保留

原始 native transcript 保留在原位置，`CLAUDE.md`、OB、MCP 配置和客户端聊天不动。每次明确放下的备份位于私有 `SHIM_SESSION_DIR/retired/<随机编号>/`，包含原 `state.json`、可用检查点和原生记录副本。备份不会被活跃检查点的清理任务删除；这些文件含私密对话，不能提交到公开仓库。

备份失败时不切换活跃状态；重启校验发现损坏时明确报错，不静默清空历史。页面不提供一键回滚，以免覆盖后续对话。需要人工恢复时，应先停服务并备份当前卷，再从选定目录恢复 `state.json` 和其中引用的检查点；保留现有 `projects` 存储，重启后由原生恢复流程校验并续接。

## 4.6 的 1M 配置

部署设置 `OPUS_46_CONTEXT=1m` 后，保存的或前端传入的 `claude-opus-4-6` 会解析为 `claude-opus-4-6[1m]`。同一原生会话可以续接，无需使用“放下”。窗口监测默认线为 967,000 token；若 CLI 报告更低的实际压缩线，仍以较低值保护归档。原有归档比例、压缩钩子、闸门设置继续生效。

1M 的监测配置不是上游账号能力证明，也不会改变订阅额度；实际模型回执可在 `/admin/window` 查看。4.6 无 1M 后缀时监测线为 167,000；显式设置的其他 `WINDOW_LIMIT` 数值仍保留。

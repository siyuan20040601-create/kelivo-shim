# 小纸条(TG 折叠卡片)

来自交接邮件《Telegram「小纸条」通用实现思路》的基础版实现。
他想留话时调 `leave_note(title, content)` 工具 → 她的 TG 出现折叠卡片
(标题+时间+一角预览)+ 三个按钮:**拆开纸条 / 🤍喜欢 / ✍️回信**。

- **拆开**:原地展开全文(editMessageText),可收起;只记第一次(幂等);
- **喜欢**:开关式爱心,连点不累计,取消也记录;
- **回信**:ForceReply 输入,每张纸条只收一封;提交后作为结构化事件
  **进入同一条会话队列并立即唤醒他**,绝不另开会话;重试/刷新靠
  `tg-note:<note_id>` 幂等键去重,同一封回信只送达一次;
- **安静事件**:拆开/点赞不打断他,攒着随她下一条消息捎给他(一行括号说明);
- 任何按钮操作都校验 chat/user/纸条归属,callback 一律 answerCallbackQuery;
- 纸条存持久卷 `/persona/notes/notes.json`(可用 NOTES_FILE 覆盖),TTL 60 天;
  正文不进日志,/debug 只报条数。

依赖:TG 已配置(TG_BOT_TOKEN+已锁定聊天)+ 便签功能开启(STATUS_WRITE_TOKEN,
因为 leave_note 挂在同一个回环 MCP 端点上)。工具失败一律降级为文字告知他,
不吞他的发言。

## 信纸页(Telegram Mini App 版,note-app.js)

设 `NOTE_APP_URL=https://<本服务公网域名>`(必须 https,TG 对 web_app 按钮的硬要求)
后,「拆开纸条」从原地展开换成打开一张信纸页:奶油信纸、楷体、格线正文、
左上可按的爱心(与聊天卡片 ❤️ 同一份状态)、右下角蜷睡的原创奶白小猫、
底部「收好纸条」(Telegram.WebApp.close)。不设该变量 = 一切如旧。

- `GET /note-app`:静态页,零数据(公网可见无所谓),CSP 锁死只允许内联与
  telegram.org 官方脚本;内容一律 textContent 渲染,不拼 HTML;
- `POST /note-app/api/note|like`:每次验 Telegram WebApp **initData 的 HMAC 签名**
  (secret=HMAC("WebAppData", bot_token),对排序后的 key=value 行再 HMAC,
  timingSafeEqual 比对),auth_date 只认 24h 内,且 user.id 必须等于她的 chat id ——
  链接外传也打不开;纸条不存在给人话 404;
- 首次成功取件 = 「拆开」安静事件(幂等),信纸页点爱心会顺手刷新聊天卡片按钮;
- 旧卡片(带 callback 展开按钮)不受影响,原路径全保留。
